# Security scan

Trivy scans both container images (backend and frontend) in the pipeline,
looking for HIGH and CRITICAL vulnerabilities in the operating system packages
and in the Python and Node libraries inside each image. It fails the build only
when a fix already exists (`ignore-unfixed`), and it scans the very image that is
pushed afterwards. A clean result means no known and fixable HIGH or CRITICAL
issue at the time of the scan. It does not prove the images are safe forever,
because new CVEs are published every day, so the scan runs again on every push.

What the real results were:

- The first pipeline runs of this project failed on purpose. The backend image had 7 HIGH findings (old `starlette`, `urllib3`, `msgpack` and `setuptools`) and the frontend image had 41 findings in old Alpine packages such as `openssl` (2 CRITICAL, 39 HIGH). They were fixed by upgrading the Python packages, removing `pip` and `setuptools` from the runtime image, and moving to a current `nginx-unprivileged` base image.
- After the upgrade to the newest base images and packages (see [VERSIONS.md](VERSIONS.md)), both scans come back clean: 0 vulnerabilities on `debian 13.7` and on all Python packages for the backend, 0 on `alpine 3.24.2` for the frontend.
- The gate was proven once. On a throwaway branch an old `urllib3` 1.25.8 was added to the backend image. Trivy reported 7 HIGH findings with fixes available, exited with code 1, and the push and the deploy were skipped. The branch was deleted afterwards (`docs/screenshots/08c-trivy-gate-red-run.png`).

Supply chain: in March 2026 the Trivy GitHub Actions were compromised (CVE-2026-33634,
76 of 77 version tags of `aquasecurity/trivy-action` were force-pushed to malicious
code). This repository pins the action to the full commit SHA of v0.35.0, the one
release the advisory names as unaffected, and sets the Trivy program to v0.76.0.
All other actions are pinned to commit SHAs as well.

Other measures: both images run as a non-root user, no secrets are stored in git
(the database password is generated by Helm, the Grafana password is read from a
Kubernetes secret, GitHub signs in to AWS with OIDC and no access keys), and the
pipeline role can only touch the `ironpass` namespace.
